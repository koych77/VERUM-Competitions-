# Проверка дизайн-альбома

Дата: 13 октября 2026.

## Автоматическая проверка

Команда: `node design/atlas/validate.cjs`.

Результат: PASS — 89 уникальных экранов, 227 ссылок на существующие экраны. Проверены обязательные свойства, рендер каждого экрана, отсутствие undefined, уникальные ID полей, наличие локальных изображений, фильтр родителя и сохранение контекста Алисы/Максима в общих шагах.

Синтаксис `atlas.js` и `screens.js` проверен через `node --check`.

## Проверка в браузере

- Codex In-app Browser, локальный статический сервер, без подключения к API VERUM.
- Режим «Все»: реально отрисованы 89 `.phone`; у всех отсутствует горизонтальное переполнение контейнера; логотипы загружены.
- Адаптивные размеры: 1440 × 1100 и 390 × 844. У альбома и проверенного мобильного экрана нет горизонтального скролла. В узком альбоме телефон занимает доступную ширину, а не буквально 390 px.
- Визуально просмотрены главная U01, состав тренера T01, список организатора O07, родительский путь U04/P06/U06 и все шесть сгенерированных листов.
- Пройден путь P05 → U04 → P06 → U06: Алиса, 9 лет, Kids 7–9, номер VR-207; взрослый профиль не подставляется вместо ребёнка.
- Нажатие отправки при выключенных согласиях оставляет P06 и показывает пояснение. После установки двух галочек открывается U06 с ожиданием проверки, не с ложным подтверждением участия.
- В журнале ошибок браузера для проверенной сессии — пустой список.
- Полный снимок альбома с открытым профилем сохранён в `preview-atlas.jpg`.

## Ограничения проверки

Это не тест работающего сервера и не юридическая/безопасностная сертификация. Не проверялись live Telegram, авторизация, доставка сообщений, база, реальные оплаты, фактическая конкурентная подача, восстановление резервных копий, полноценный screen-reader и печатный PDF. Сохранение данных в альбоме намеренно отсутствует.

Все 89 экранов проверены на рендер/ссылки/горизонтальное переполнение; не заявляется отдельная визуальная экспертиза каждого из 89 экранов на каждом устройстве. Повторно используемые экраны показывают образец, а не все варианты каждого человека. Выборы в списках и select — фиксированные дизайн-состояния. Контекст родительского пути реализован для демонстрации, остальные ветвления описаны в SPEC.md.

На растровых AI-листах замечены текстовые расхождения: дополнительные категории, разные счётчики и возрастные подписи. Они обозначены как иллюстрации. Для разработки использовать точные HTML-макеты и спецификацию, а не OCR генераций.

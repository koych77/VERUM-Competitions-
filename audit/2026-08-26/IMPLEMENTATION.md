# VERUM Competitions — отчёт об улучшениях

Дата реализации и повторной проверки: 26 августа 2026 года.

Исходный подробный аудит находится в `audit/2026-08-25/REPORT.md`. Этот документ фиксирует, что именно изменено после аудита и какой практический результат получает пользователь или администратор.

## 1. Сохранность существующих участников

- До миграций создана локальная сжатая копия production PostgreSQL: 11 таблиц, 772 строки, SHA-256 сохранён рядом с файлом. Каталог исключён из Git.
- В копию входят все 134 пользователя, 193 регистрации, 256 связей регистраций с номинациями, профили, тренеры, ученики, события и справочники.
- Автоматическое удаление найденных дублей не выполнялось: неоднозначные данные нельзя объединять без решения организатора.
- Удаление мероприятия с существующими заявками запрещено сервером. Для завершённых событий используется архив, который сохраняет регистрации.
- Startup-DDL отключён в production. Схемой теперь управляет только Alembic.
- Миграции проверены на чистой базе и на legacy-схеме, где физические колонки уже есть, а Alembic отмечен как `0001`. Оба сценария проходят до `0008 head`.

## 2. Авторизация и защита персональных данных

### Было

Telegram ID фактически использовался как пароль: его можно было передать через header/query, dev-login был доступен в production, а часть profile/registration endpoint позволяла читать или менять чужие данные.

### Стало

- Telegram `initData` проверяется по подписи, сроку жизни и `auth_date`.
- После проверки backend выдаёт ограниченную по времени HMAC-сессию Bearer.
- Dev-login работает только в development при явном `ALLOW_DEV_AUTH=true`; production с таким флагом не запустится.
- Админские API больше не доверяют `X-Telegram-Id` и `admin_id` в URL.
- Profile, student и registration API отдельно проверяют текущего пользователя и ownership.
- Даже администратор не может случайно создать личный профиль или заявку от имени другого пользователя через подменённый payload; административные действия вынесены в отдельные endpoint.
- CORS ограничен доверенными origin, добавлены CSP, nosniff, referrer и permissions headers.
- Неизвестный `/api/*` возвращает JSON 404 и больше не маскируется SPA-страницей.

## 3. Надёжность регистрации

- Backend проверяет, разрешён ли организатором выбранный тип: полная, быстрая или тренерская регистрация.
- Повторная отправка одной заявки возвращает существующую запись, а не создаёт дубль.
- Для PostgreSQL добавлена транзакционная блокировка пары `пользователь + мероприятие`.
- Тренер, новые ученики и их регистрации сохраняются одной транзакцией. Частично созданных учеников после ошибки больше не остаётся.
- Повторная тренерская отправка находит того же ученика по нормализованным данным и не создаёт копию.
- Все submit-кнопки имеют loading/disabled и обработку ошибок.
- Ошибка сети, пустой список и успешная загрузка отображаются разными состояниями.
- Дата закрытия регистрации не может быть позже даты мероприятия — правило проверяется клиентом, Excel-preview и backend.

## 4. Новый визуальный язык

Сохранена узнаваемая чёрно-оранжевая идентичность VERUM, но интерфейс переведён с набора локальных стилей на дизайн-систему.

- Цвета, поверхности, границы, радиусы, тени, размеры и отступы вынесены в tokens.
- Основной шаг отступов: 4/8/12/16/24/32 px; карточки и формы больше не используют случайные значения.
- Границы стали спокойнее: нейтральный divider для структуры, orange — только для active/focus/primary.
- Единые высоты контролов и области нажатия не меньше 44 px.
- Добавлены видимые keyboard focus, hover, active, disabled, loading, success и error состояния.
- Поля получили корректные `label`, required-маркеры, hints через отдельную кнопку, `aria-describedby` и `aria-invalid`.
- Нативные select снова визуально распознаются как select.
- Учтены Telegram safe-area и `prefers-reduced-motion`.
- CSS разделён на tokens, base, components, pages, admin и responsive вместо одного файла примерно на 1 200 строк.

## 5. Пользовательский путь

### Главная

- Компактная sticky-панель: логотип, «Регистрация», доступная только администратору вкладка «Админка» и нейтральный индикатор подтверждённой сессии.
- Telegram ID больше не показывается пользователю.
- Карточка события получила ясную иерархию: статус → название → дата/место/дедлайн → номинации → secondary/primary action.
- Длинные названия и адреса переносятся целиком, без разрыва по буквам.
- Есть skeleton loading, retry error и объясняющий empty state.

### Выбор сценария

- Технические названия заменены вопросом «Кого вы регистрируете?».
- Варианты объясняют последствия: сохранить свой профиль, быстро зарегистрироваться только на событие или собрать общую заявку учеников.

### Регистрация участника

- Длинная форма разделена на три этапа: `Данные → Номинации → Проверка`.
- Видно текущий и завершённые шаги.
- Номинации подбираются по дате рождения и полу, показывают счётчик выбранных.
- Командные поля появляются только при выборе командной номинации.
- Перед отправкой есть summary участника, клуба, тренера и номинаций.
- Основной CTA закреплён снизу и учитывает safe-area.
- Success-screen подтверждает событие, участника и выбранные номинации.

### Тренерская регистрация

- Профиль тренера и ученики визуально разделены.
- Новых и сохранённых учеников можно собрать в одну заявку.
- Ошибка подбора номинаций больше не выглядит как пустой список: есть понятный error state.
- Двойное нажатие проверено в браузере и на backend: создаётся одна регистрация и один ученик.

### Мои заявки

- На главной появился защищённый личный раздел.
- Пользователь видит все свои заявки, включая закрытые и архивные события, участника, тип регистрации и номинации.
- Это устраняет необходимость повторно открывать форму только ради проверки, сохранились ли данные.

## 6. Админка

- На desktop используется двухколоночное рабочее пространство с постоянной боковой навигацией.
- На mobile разделы превращаются в понятную сетку без скрытого горизонтального scroll.
- Статусы локализованы; primary, secondary и destructive действия визуально разведены.
- События по умолчанию создаются как черновики.
- Обязательные поля отмечены, ошибки проверяются в порядке пользовательской формы.
- Архивирование явно сообщает, что заявки сохранятся.
- Полное удаление объясняет, что оно доступно только при отсутствии заявок; backend повторяет эту защиту.
- Excel template/export скачиваются авторизованным fetch, без Telegram ID в query string.
- «Люди» объединяет поиск по участникам, тренерам и ученикам, показывает counts и отдельные empty states.
- Все затронутые edit/delete/toggle действия получили catch и понятное сообщение, вместо необработанного Promise.

## 7. Безопасная рассылка

- Перед отправкой администратор видит total, уже обработанных, оставшихся и пример персонального сообщения.
- Введён постоянный `campaign_key` и журнал доставки по пользователю.
- Для многосоставного Telegram-сообщения сохраняется номер последней отправленной части.
- Повторный запуск пропускает `sent/blocked`, продолжает незавершённые сообщения и не рассылает всё заново.
- Параллельные запросы используют атомарное получение delivery-записи с unique constraint.
- Повторная отправка покрыта интеграционным тестом: второй запрос отправляет 0 сообщений.

## 8. GitHub и Railway

- Добавлен CI: Ruff, pytest, Alembic from-empty check, pip-audit, frontend build, npm audit и production Docker build.
- Добавлен Dependabot для pip, npm и GitHub Actions.
- Docker build использует `npm ci`, приложение запускается non-root пользователем.
- Railway перед запуском применяет `alembic upgrade head`.
- Healthcheck переведён на `/api/ready`, который реально проверяет БД.
- Добавлены restart policy и production runtime validation.
- Реальные admin ID удалены из публичного `.env.example`.

## 9. Проверки

- Ruff: успешно.
- Pytest: 12 интеграционных/безопасностных тестов успешно.
- Alembic: чистая база → `0008 head` успешно.
- Alembic: legacy production-shape (`0001` + уже существующие поля) → `0008 head` успешно.
- Vite production build: успешно.
- npm audit: 0 известных уязвимостей.
- pip-audit: известных уязвимостей нет.
- Playwright: полный участник, тренер, двойной submit, личные заявки, админка, поиск, create validation, broadcast preview и production auth error.
- Viewports: 320, 375, 768 и 1440 px; горизонтального overflow нет.
- Browser console: ошибок нет; остаётся только ожидаемое предупреждение Telegram SDK вне Telegram WebView.

## 10. Что намеренно не менялось автоматически

- 9 исторических групп потенциальных дублей регистраций: требуется решение организатора.
- Регион Railway US East: перенос базы в EU требует отдельного downtime/restore плана.
- Большое физическое разбиение `App.jsx` и router-файлов: CSS и критическая бизнес-логика уже разделены, дальнейший механический перенос лучше делать отдельной задачей после стабильного production rollout, чтобы не увеличивать риск текущего релиза.
